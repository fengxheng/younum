# 有数 YOUNUM

> 把账单，整理成生活。

Android 记账整理 App：**导入月账单 → 逐笔确认用途 → 生成可对账的月度消费概况**。

它**不是**流水账工具。它不要求你从今天开始每天记一笔，也不做预算与打卡 ——
它的假设是：你已经有账单（微信、支付宝、银行卡都能导出），
你要的是**一个月花十几分钟，把这个月的钱看清楚**。

所以主流程设计成「整理」而不是「记账」：把账单导进来，
一笔一笔地给它一个用途，整理完就能看到分类占比、趋势、日均，以及跟上月比怎么样。

**当前状态**：功能闭环，已在真机日常使用。33 个设计状态全部实现；
`flutter test` 653 项、真机测试 55 项通过（平板竖屏另有走查，见 `docs/MANUAL_CHECKS.md`）。

## 功能

### 导入（微信 / 支付宝 / 银行卡 / 通用表格）

- 支持 **CSV**（UTF-8 带不带 BOM 都行；GB18030/GBK 自动识别）与 **XLS/XLSX**
  （后缀 `.xls` 但内容其实是 xlsx 的也能认出来）。
  ⚠️ 判断的是**内容**而不是后缀：真正的老式 `.xls`（OLE2/BIFF 那种二进制）
  读不了，那时会明确让你在表格软件里另存一份，而不是给一页乱码。
- **一份账单也可以直接从系统「分享」到有数**：微信、文件管理器里选「分享 / 用其他
  应用打开」都能进来。应用会自己认这是不是一份账单、按内容认出来源（微信 / 支付宝 /
  通用），认成功就**直接落到「确认导入」页**；读不了或认不出来时会说清原因。
  同一份分享只会导一次。
- 三个来源入口：**微信支付 / 支付宝 / 通用表格**。银行卡账单不单独设入口 ——
  它按**整套表头**识别后自动启用银行专用适配器（所以「交易类型」这种列名
  不会把微信账单带偏）。
- 表头认不出来时不猜：进**字段映射页**，把列手工指给字段。
- 核对页会列出：本次新增几笔、合计多少、需要检查的行、**疑似重复**。
- 疑似重复分两级：**同源**（同一份账单里的同一个单号）与**跨来源**
  （微信/支付宝的扣款都走同一张银行卡，同一笔会在两份账单里各出现一次，
  而商户名完全不同）。跨来源**只提示、不自动剔除**，逐组由你决定保留几笔。
- 提交是**一个事务**：要么整批进去，要么全不进去。中途被杀也有恢复逻辑，
  不会留下半批数据、也不会让你重复入账。
- **导入记录**里可以看每一批的来处与结果，也可以**撤回**（只删「只有这一批引用、
  而且你还没整理过」的那些，你做过的工作不会被撤掉）。
- 异常明细可以**导出成 CSV**（页面只列前 50 行，导出的是完整清单）。

### 整理（主流程）

- 逐张卡片确认用途：**右滑确认**、**左滑稍后**，也可以点按钮。
  手势阈值、轴锁定、回弹、动画都按设计稿实现；**先写库再播动画**，
  失败就回弹并保留你的选择。
- **拆分**：一笔消费可拆给多个用途，每项大于 0 且合计**精确等于**原金额。
- **交易性质**：收入 / 转账 / 退款 / 不计入统计。排除统计必须写明原因。
- **退款**：关联到原消费，可以跨月；拆分过的消费要求明确「抵扣到哪几项、各多少」；
  也能**取消关联**让退款回到待核对。
- **撤销**：记录、队列位置、备注、用途一起还原。
- 整理进度可中断续做（重启后还在原来的位置）。

### 月报与导出

- 月度概况、分类占比、趋势（近 6 个月）、明细列表、月份切换。
- **范围完整性由你显式确认**：没确认就标「部分账单」，日均按已覆盖天数算，
  环比也不显示 —— 不猜。
- 分享与导出：
  **月报海报 PNG** —— 用 `dart:ui` 现画，**直接存进相册**（`Pictures/有数`），
  不弹选择器；每次进来默认隐藏金额，而且隐藏是**文件层面**成立的，不靠屏幕遮罩。
  **明细 CSV** —— 走系统的「创建文档」流程由你选保存位置；
  文本列防公式注入，金额列保持数字语义。

### 分类

- 新建、改名、换图标（12 个内置矢量图标 + 用自己的图片，居中裁成 256×256）。
- **用途快捷项**：整理卡片上显示哪几个用途、按什么顺序，由你决定。
  「分类管理」顶部会直接写出当前那几个；点进去能**拖动手柄改顺序**，
  也能移除 / 添加。上限 8 个（两行）不是可以商量的数字 ——
  确认按钮与「撤销 / 稍后 / 更多操作」必须留在屏幕上（指南 6.2）。
  没配过的人看到的还是原来那 8 个。
- **删除默认归档**（历史引用继续有效，归档后能在底部恢复）。
- **合并**：把源分类上的账目真的迁到目标分类，然后把空掉的源分类归档。
  只允许同层级合并；源下面还有细分用途时会先让你处理它们。

### 我的

主题（6 套预设 + 自定义取色，拖动即时预览、松手才落盘）、分类管理、导入记录、
隐私与数据、整理提醒、整理进度与保存状态、使用帮助、
**检查更新**（GitHub Releases → 系统下载器 → 系统安装器）。

**体验示例账单时可以退出**：进演示账本之后，首页那个「示例账本」徽标可以点
（弹出说明 + 退出），「我的」页顶部也有一条「退出示例账本」。
**退出不删任何东西** —— 样例数据仍在它自己的账本里，空首页上点
「先用示例账单体验」就能回去。

启动时会**静默查一次**新版本：查到就弹一个层告诉你（可以「去更新」/
「忽略这个版本」/「以后再说」）。点过「忽略」的版本不再提，直到出现更高的版本；
「以后再说」什么都不记，下次启动还会提。查不到（断网、限流）什么都不弹 ——
应用不拿「没查到」当「已是最新」。

### 系统能力

| 能力 | 实现 |
| --- | --- |
| 每月整理提醒 | WorkManager 后台任务 + 通知（按自然日历推算下次时间，不是固定 30 天） |
| 数据库加密 | SQLCipher；口令由 **Android Keystore** 保管，钥匙不出设备 |
| 在线升级 | 只读 GitHub 上一个公开的版本号；安装包经系统下载器与系统安装器 |
| 分享导入 | 清单声明 CSV / XLS / XLSX 的 MIME（另含 `application/octet-stream`，因为很多发送方报不出类型）；文件是不是账单由**内容**判断 |
| 平台通道 | 共 4 条：`files`（选文件 / 读分享进来的文件 / 选图 / 保存文档）、`reminder`、`security`、`update` |

界面全部自己实现（颜色派生、组件、图表），**没有引入任何第三方 UI 或状态管理库**。

### 这台机器上的三个环境坑（不是代码问题，遇到别改业务代码）

1. **`sdkmanager.bat` 会崩**（`NTSTATUS 0xC0000409`），所以任何要联网补装
   Android SDK 组件的操作都会失败。
2. 因此 `android/app/build.gradle.kts` 里把 **`ndkVersion` 显式写成**
   本机已装的版本，避免 AGP 去联网下载 NDK。
   （本工程与全部依赖都没有原生代码要编译。）
3. **工程目录不要放在中文路径或 OneDrive 同步目录下**：AGP 会直接拒绝构建，
   Dart analysis server 会崩。当前工程在 `D:\dev\younum`。
   另外因为 pub 缓存在 C 盘、工程在 D 盘，**Kotlin 增量编译被关掉了**
   （跨盘符会让 Kotlin 缓存报 `different roots`）。

## 构建与运行

在 `app/` 目录下执行：

```powershell
flutter pub get

flutter devices                        # 确认设备已连接
flutter run -d <device-id>             # 开发运行（debug）
flutter run -d <device-id> --profile   # 测性能用这个，不要用 debug 判断性能

flutter build apk --debug              # 调试包
flutter build apk --profile            # 性能对照包
flutter build apk --release            # 发布包（正式签名，见下一节）
```

产物都在 `build/app/outputs/flutter-apk/`。

### ⚠️ 三件必须知道的事

1. **改了 Kotlin / Manifest / Gradle / 依赖之后，必须 `flutter build apk --release`
   并装到真机上点开看一眼。**
   release 会跑 R8 而 debug 不会，所以「反射实例化被当成死代码裁掉」这类问题
   **只在正式包里出现**，`flutter analyze`（只管 Dart）和 debug 构建都看不见。
   真机上曾经出现过「包能装上、点开图标什么都没发生」——
   罪魁是 R8 删掉了 Room 生成的 `WorkDatabase_Impl` 的反射构造，
   而它崩在 Flutter 引擎起来**之前**，连一行 flutter 日志都没有。
   保留规则在 `android/app/proguard-rules.pro`。

2. **数据库测试必须跑在真机上。**
   外键、唯一约束、`ON DELETE RESTRICT`、事务原子性这些东西，
   只有真实 SQLite 能证明 —— 内存实现里的绿灯不算数。

   ```powershell
   flutter test integration_test/database_test.dart -d <device-id>
   ```

   顺带一提，**本机跑不了单元测试里的数据库用例**：那需要一个本机并不存在的
   `sqlite3.dll`（系统里只有给 UWP 用的 `winsqlite3.dll`）。
   把系统 DLL 改名软链过去是机器相关的做法，项目不做 —— 所以分层是
   「纯 Dart 测逻辑，真机测 SQL」。

3. **`flutter install` 装的是 release 包，而且会先卸载旧版**（数据一起没）。
   要装调试包请直接 `adb install -r build/app/outputs/flutter-apk/app-debug.apk`。
   另外**换签名等于换应用**：调试签名的包和正式签名的包不能互相覆盖。

App 不做登录。冷启动进欢迎引导（只出现一次），之后是首页。

## 签名与发布

正式签名读 `android/key.properties`（**不进仓库**，`android/.gitignore` 已忽略）。
**文件不存在时构建不会失败**，会自动回退到调试签名 —— 所以如果你要发版本，
先按 [`docs/RELEASE.md`](docs/RELEASE.md) 配好。

发布走 GitHub Releases，应用内的「检查更新」读的就是它。
⚠️ 这个仓库开了 **Release 不可变**、而且不允许通过 API 创建标签，
所以发布顺序**不能错**（先 `git push` 标签 → 建草稿 → 传 APK → 再发布）。
完整步骤、踩过的坑、发布前检查清单都在 [`docs/RELEASE.md`](docs/RELEASE.md)。

│   └── features/            界面与界面级状态（每个目录 = 一块功能）
│       ├── start/           欢迎、空首页、本月首页
│       ├── import_flow/     选来源、选文件、解析、字段映射、核对、重复、异常、完成
│       ├── organize/        卡片、全部分类、分类管理/编辑器、详情、拆分、性质、完成
│       ├── report/          概况、分类详情、趋势、明细、月份、分享
│       ├── export/          分享与导出
│       ├── profile/         我的、主题、导入记录、隐私、提醒、保存状态、检查更新
│       └── review/          设计状态走查（仅调试构建）
├── android/                 原生侧（很薄）
│   └── app/src/main/kotlin/com/younum/app/
│       ├── MainActivity.kt      4 条平台通道：files / reminder / security / update
│       ├── ReminderWorker.kt    WorkManager 任务与通知渠道
│       └── DatabaseKeyStore.kt  数据库口令的生成与保管（Keystore）
├── test/                    纯 Dart 测试与夹具 63 个文件 —— 见 test/README.md
├── integration_test/        真机测试（SQL 与外键只能在这里验）
├── docs/                    工程文档 —— 见下面的「文档索引」
└── build/                   构建产物（不进仓库）

**分层约定**（改代码时请守住）：

```text
features (界面/控制器)  →  domain (规则 + 端口)  →  data (真实实现)
                                  ↑
                            core (基础设施，与业务无关)
```

`domain/` 里**不允许**出现 `import 'package:flutter/...'`，也不允许直接碰 SQL。
界面要一个新能力，就在 `domain/repositories/` 定义端口，在 `data/` 里给实现，
由 `app/app.dart` 注入 —— 这也是为什么测试能把「选文件」「保存导出」「升级安装」
换成假实现跑完整条界面路径。

## 数据与隐私

- **所有数据只在本机。** 账单、分类、图标、导出文件都在应用私有目录或你指定的位置；
  没有账号、没有云同步、没有埋点。
- **`android:allowBackup="false"`**：账单不会被系统云备份静默上传。
  代价是换机不会自动恢复 —— 这是刻意的，不是缺陷。
- **数据库是加密的**（SQLCipher）。口令随机生成、由 Android Keystore 里的
  一把不可导出的密钥包住后存在应用私有目录；把 `younum.db` 单独拷走读不出内容。
  ⚠️ 代价必须说清：**卸载应用、清除应用数据、换手机都会让钥匙消失，数据就永久读不出**。
  所以「换机前先导出」这件事写在应用的「隐私与数据」页里。
- 权限只有 **4 个**，都能说清用途：
  `POST_NOTIFICATIONS`（每月提醒）、
  `WRITE_EXTERNAL_STORAGE`（**仅 Android 9 及以下**存相册，已用 `maxSdkVersion="28"` 限住）、
  `INTERNET`（**只用于检查更新**：读一个公开的版本号，以及经同意后下载安装包）、
  `REQUEST_INSTALL_PACKAGES`（把安装包交给系统安装器）。
  账单数据不参与任何网络请求。

## 已知限制

**明确未验证的**（不要当成已完成，逐条在 `docs/MANUAL_CHECKS.md` 里）：

- 系统文件选择器的各种异常路径（取消、选错文件、超大文件、连点两次）；
- 相册写入在各种系统版本上的表现；
- 六套主题的逐页对比度、系统字号调到最大、TalkBack、横屏旋转；
- **从微信里真的分享一份账单过来**：分享这条路已在真机上验过（系统「打开方式」
  里有有数、冷启动后落到确认导入页、读不了的文件会说实话），但走的是 adb 构造的
  intent，不是微信那份 UI；
- **启动时的新版本提示长什么样**：线上最新版就等于当前安装版，所以真机上只验到了
  「不该弹的时候不弹」；弹层本身由测试守着；
- **平板上的横屏与系统字号 2.0、TalkBack**：平板**竖屏**已经走查过
  （2026-09-26，720×1152dp，release 包）：
  正文、顶栏、弹层都限到 560dp 居中，插画不跟着屏宽变形，
  用途快捷项能拖动且重启后顺序还在，退出示例账本一整圈走通 ——
  清单在 `docs/MANUAL_CHECKS.md` 第十九节。**横屏明确不做**（需求方定）；
- **已验过、不用再列的那条**：升级之后老账单一条不少（2026-09-25，
  1.2.1+5 → 1.3.0+6 覆盖安装，首页数字与升级前完全一致）。

**已知取舍**：

- 图表与环形图是自绘的，没有第三方图表库；趋势的环比需要**连续两个范围完整的月份**，
  只有一个月数据时会显示「暂无可比月份」而不是数字 —— 这是正确行为。
- 卡片高度由内容决定（系统字号放大时页面变长、靠滚动看全），不固定屏幕总高度。
- **大屏（平板竖屏）限宽居中**：正文、顶栏、底部弹层都限制在 560dp 并居中
  （指南 6.3），不把手机 UI 无限拉宽。**横屏没有适配**，也没有做双栏/侧栏导航；
  另外空首页那张装饰插画在**系统字号 2.0** 下会溢出（已知问题，未修，见
  `docs/MANUAL_CHECKS.md` 的「已知未验证」）。
- 应用内升级时，国内手机（小米/HyperOS 等）会多一层系统提示
  （「未查询到此应用的 ICP 备案信息」），点「继续安装」即可 ——
  个人项目没有备案，这是正常的。

**环境限制**：`sdkmanager` 不可用、NDK 版本写死、Kotlin 增量编译关闭 ——
见上文「环境要求」。
