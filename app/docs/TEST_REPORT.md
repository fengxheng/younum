## 2. 测试都覆盖了什么

* **纯逻辑**（不需要设备）：金额与拆分、月报口径与环比、退款与拆分退款、
  分类管理、图标规则、导入解析（表头识别、字段映射、逐行标准化、
  去重与跨来源疑似）、导出（CSV 公式注入防护、海报内容与隐私开关）、
  提醒的日历推算与状态机。
* **引擎**：海报 PNG 真的画出来（文件头、IHDR 尺寸、能重新解码）、
  分类图片的解码 → 裁方 → 缩放 → 重新编码。
* **界面**：把真实的 `YounumApp` 挂起来走完整路径（导入、整理、月报、
  分享导出、提醒设置），文件来源、渲染、保存都用可注入的假实现 ——
  这也正是当初把「能力」做成端口的原因。导入异常明细的导出也在其中：
  特意用 55 行坏行断言「页面只列 50 行，导出的文件里 55 行一行不少」。
* **选择用途与细分用途**（本轮新增）：`category_pick_widget_test.dart` 3 条锁
  「点一下即选中、返回即带值、只是看一眼就不带值」；`sub_category_widget_test.dart`
  5 条锁「在细分用途页新建 → 回选择页就能选到并确认」「改名后 ID 与父级不动」
  「两个入口都能到」「emoji 存进 `iconKey` 并画出来」「填文字当场报错」。
  改名那条**第一次跑就是红的**（报 `Expected: '点外卖' Actual: '外卖'`），
  暴露的正是「改完名字保存按钮还是灰的」这个真机缺陷（`DECISIONS.md` 82 第 1 条）；
  另一条红是 SnackBar 的 hero tag 老毛病（78 节末尾记着），改成先等提示条收掉再导航。
  底部留白那条（82 第 2 条）**测试看不见** —— 只在真机上滚到底才发现。
* **字号放大**：默认字号下卡片就是设计高度，字号 2.0 时卡片必须**真的长高**
  （断言的是高度，不是「没报错就算过」），2.0 下走完四个标签页不溢出，
  360dp 窄屏 + 2.0 金额缩得下。滑卡手势另有一组回归（卡片换没换作为证据），
  并在字号 2.0 下再验一次。
* **平板竖屏（720×1152dp）**：主要页面走一遍一处不溢出；正文正好
  560dp 且居中；引导页/空首页的插画不跟着屏宽变形（宽度 < 400dp 且居中）；
  弹层里的按钮也跟着限宽。三条实现都做过「拆掉就变红」的反向验证（见
  `DECISIONS.md` 73 节）。
* **用途快捷项**：默认就是内置那 8 个（老用户升级上来不变样）、按下单顺序与子集
  显示、自建分类可以进来而细分用途不行、归档的不显示且**不自动补位**、上限 8 个、
  重复 ID 去重、写偏好失败时列表**不变**并把原因说出来。界面那一组还包括
  **拖动第二行到第一格后顺序真的落盘**、只剩一个时不能移除、满了显示「已满」。
* **退出示例账本**：「我的」那一行退出后回到自己的账本且能走回演示账本、
  徽标 → 弹层 → 退出、「继续体验」什么都不改、自己的账本里不该出现演示账目的痕迹。
* **一笔钱的方向**：收入那笔的卡片徽标必须是「收入」（修之前红，报的就是
  `Expected: '收入' Actual: '支出'`）、消费那笔仍然是「支出」、朗读文本也跟着走；
  详情页不能把收入那笔说成「待确认用途」，面板里不能再出现写死的
  「商户消费」与 `•••• 0826`，有单据号时要显示它的后四位（见 `DECISIONS.md` 77 节）。
* **新建分类马上能用**：分类管理 → 新建 → 回卡片选中它 → 右滑，必须真的确认并落库
  （修之前红，报 `Expected: <1> Actual: <0>`）；手势失败不许静默 ——
  「选中的用途换不成分类」与「一个用途都没选就右滑」都要说出原因
  （见 `DECISIONS.md` 78 节）。
* **在线升级**：GitHub 响应的各种残缺形态（没有 APK、tag 里没带 build number、
  根本不是对象）、版本号解析、忽略语义（只忽略这一版，更高版本照旧提示）、
  以及**「查不到」绝不能被说成「已是最新」** —— 规则、控制器、界面三层各有用例。
  本轮补了**启动时的提示**那一层（8 条）：只在有新版本时弹、只弹一次、
  用户自己查过就不再弹、忽略过的版本不弹、出现更高版本还会提、
  「以后再说」与「忽略」不是一回事（一个不记、一个写进偏好）、三个按钮不贴在一起、

* **分享进来的账单**（`share_import_widget_test.dart`，6 条）：成功时直接落到
  「确认导入」且数字来自真实解析；表头认不出时去字段映射页；老式 `.xls`
  与读不了的文件都要用**看得懂的句子**说清原因；同一份分享**只导一次**
  （回到前台不会重导）。域名侧另有 5 条：OLE2 按内容识别、按内容认来源
  （微信 / 支付宝 / 通用）、读不了的东西不会被硬说成某个来源，
  以及「分享进来的微信账单与从入口导入的算**同一个来源**」（否则同一笔只能报成
  「疑似重复」）。
* **分类**：新建真的落库、同级重名被拒且不写、改名保留稳定 ID、图标可换可恢复、
  图片图标的完整链路、删除默认归档且能从「已归档」恢复、历史引用不受影响；
  **合并**单独一组：规则（同层级 / 目标不能已归档 / 源不能还有细分用途）、

  退款分配改指向且合计不变、被拒时一行都不写。真机上另有 3 条走真实 SQL。
* **真机 SQLite**：事务原子性、外键与唯一约束、迁移链、导入暂存/提交/撤回、

## 4. 大文件

`test/import_large_file_test.dart`（整组约 8 秒）：

* 6 万行 CSV：全部解析、统计正确、能提交；
* 2 万行 → 4 万行：耗时比值必须远小于 4，用来接住「复杂度写错」这类问题；
* 同一份文件再导一次：全部判成同源重复，一笔不入。

⚠️ 这组跑的是**测试用的内存实现**。真机 SQLite 上几十万行的提交**没有测过**
—— 真实账单量级（几千行）在真机上验过，但「极大文件在真机上提交的耗时」
属于未验证。

## 6. 未验证 / 已知限制

以下都在 `docs/MANUAL_CHECKS.md` 里有对应条目，**发布说明里要如实写明**：

* 涉及系统界面的路径（文件选择器、相册写入、系统通知设置）只能人工走；
* 桌面与 Web 不支持选文件、保存、提醒（注入的是「不支持」实现，入口显灰）；
* 应用私有存储**不等于**数据库已加密，本版没有实现加密；
* CSV 是数据导出，**不是**可还原的备份；
* 提醒的送达时间由系统调度决定，晚几分钟到十几分钟都属正常；
* 这台设备上 Impeller 会白屏（设备端图形问题），需 `--no-enable-impeller`；
* 空首页的装饰插画在系统字号 2.0 下溢出 254px / 160px（本轮用大字号用例
  撞出来的**既有**问题，没修，已记进 `MANUAL_CHECKS.md`）；
* 启动时的新版本提示**没能在真机上看到**：线上最新版就是当前安装的 1.2.1+5，
  没有可提示的版本 —— 它是正确行为，但「弹层长什么样」只有测试与那 8 条用例撑着；
* 「从微信里真的分享一份账单过来」没走过：真机验证用的是 adb 构造的
  `ACTION_VIEW` + 带授权的 `content://`（同一个原生通道，但不是微信那条 UI）。

### 本轮没跑真机 `database_test.dart`（写清原因，不当已验证）

改动碰到了 `lib/domain/repositories/import_workflow.dart`，按 `AGENTS.md` 第四节的表
本该跟着跑一遍真机 SQL 套件。**但它没跑**，原因是现实风险而不是偷懒：

* `flutter test integration_test/…` 会装一个 **debug 签名**的测试包，而这台设备上
  现在是**正式签名**的包、里面有需求方的真实账单。签名不一致时安装要么失败，
  要么按工具的行为先卸载 —— **卸载就等于数据没了**（密钥在 Keystore 里）。
* 改动本身不碰 SQL 与存储实现：`_readTable` 只是把「字节 → 表格」那段原样抽了一处
  （CSV / XLSX 两条路的行为没变，旧用例仍然盖着），新增的 OLE2 判断在**写库之前**
  就返回了，`sniffImportSource` 不写库。

**要在真机上复跑的话**：用另一台设备，或先把账单导出来再跑。这一条在本轮
**算未验证**，发布说明里如果要提真机验证，不要把 SQL 套件说成跑过。
