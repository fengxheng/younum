## 2. 测试都覆盖了什么

* **纯逻辑**（不需要设备）：金额与拆分、月报口径与环比、退款与拆分退款、
  分类管理、图标规则、导入解析（表头识别、字段映射、逐行标准化、
  去重与跨来源疑似）、导出（CSV 公式注入防护、海报内容与隐私开关）、
  提醒的日历推算与状态机。
* **引擎**：海报 PNG 真的画出来（文件头、IHDR 尺寸、能重新解码）、
  分类图片的解码 → 裁方 → 缩放 → 重新编码。
* **界面**：把真实的 `YounumApp` 挂起来走完整路径（导入、整理、月报、
  分享导出、提醒设置），文件来源、渲染、保存都用可注入的假实现 ——
  这也正是当初把「能力」做成端口的原因。导入异常明细的导出也在其中：
  特意用 55 行坏行断言「页面只列 50 行，导出的文件里 55 行一行不少」。
* **字号放大**：默认字号下卡片就是设计高度，字号 2.0 时卡片必须**真的长高**
  （断言的是高度，不是「没报错就算过」），2.0 下走完四个标签页不溢出，
  360dp 窄屏 + 2.0 金额缩得下。滑卡手势另有一组回归（卡片换没换作为证据），
  并在字号 2.0 下再验一次。
* **真机 SQLite**：事务原子性、外键与唯一约束、迁移链、导入暂存/提交/撤回、
  退款关联、图标资源、进程被杀后的导入恢复。测试库与正式库隔离。

## 4. 大文件

`test/import_large_file_test.dart`（整组约 8 秒）：

* 6 万行 CSV：全部解析、统计正确、能提交；
* 2 万行 → 4 万行：耗时比值必须远小于 4，用来接住「复杂度写错」这类问题；
* 同一份文件再导一次：全部判成同源重复，一笔不入。

⚠️ 这组跑的是**测试用的内存实现**。真机 SQLite 上几十万行的提交**没有测过**
—— 真实账单量级（几千行）在真机上验过，但「极大文件在真机上提交的耗时」
属于未验证。

## 6. 未验证 / 已知限制

以下都在 `docs/MANUAL_CHECKS.md` 里有对应条目，**发布说明里要如实写明**：

* 涉及系统界面的路径（文件选择器、相册写入、系统通知设置）只能人工走；
* 桌面与 Web 不支持选文件、保存、提醒（注入的是「不支持」实现，入口显灰）；
* 应用私有存储**不等于**数据库已加密，本版没有实现加密；
* CSV 是数据导出，**不是**可还原的备份；
* 提醒的送达时间由系统调度决定，晚几分钟到十几分钟都属正常；
* 这台设备上 Impeller 会白屏（设备端图形问题），需 `--no-enable-impeller`。
