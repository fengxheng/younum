# 需要人手点的检查清单

自动化能覆盖的部分已经写进 `test/`（单元测试，纯 Dart）与 `integration_test/`
（真机 SQL 与平台通道）。**下面这些必须有个人在场**：要么需要真实设备上的系统
界面，要么需要人的眼睛判断「看起来对不对」。

每做完一项就把方框改成 `[x]`，并写上日期与设备，便于回看是哪一版验的。

> 为什么要把这份清单单独写出来：指南 9 阶段 7 要求「无法验证的设备 / 格式
> 必须如实列为未验证」。把未验证的事情列清楚，比让它含糊地混在「已完成」里
> 诚实得多。

## 一、导入：系统文件选择器（当前最关键的未验证项）

这几项都没法自动化：选择器的界面随 Android 版本与厂商而变，脚本点它不可靠。

- [ ] **在系统选择器里真的选一份微信账单 XLSX**（微信现在导出 xlsx，不是 csv），
      看是否进到核对页，且笔数 / 金额与文件内容对得上
      —— 解析本身已用真文件验过，这里要验的是**选择器那一段**
- [ ] **在系统选择器里真的选一份支付宝账单**（支付宝的说明行更多，也是 xlsx）
- [ ] **选一份 GBK 编码的 CSV 账单**，确认没有乱码，且核对页上显示的编码是 GBK
- [ ] **选一个不是账单的文件**（例如一张图片）：应该明确报错，
      而不是"导入成功 0 笔"
- [ ] **在选择器里按返回 / 取消**：应安静地回到选文件页，不弹错误提示、
      按钮仍可点
- [ ] **选一个很大的文件**（> 64 MB）：应被挡下并说明上限
- [ ] **连续快速点两次「选择账单文件」**：只能开出一个选择器
- [ ] **选完文件后立刻切到别的应用再回来**：解析结果还在（或能重新开始），
      不出现白屏

## 二、导入：字段映射与重复

- [ ] **导入一份表头认不出来的 CSV**（例如把列名改成"日期戳/摘要/数额"）：
      应进入字段映射页，且能看到文件前几行原文
- [ ] 映射页上**故意把同一列指给两个字段**：按钮应变灰并说明原因
- [ ] 映射页上**故意漏掉必填项**：同上
- [ ] **同一份文件导入两次**：第二次应提示这些记录已经导入过，
      且账本里的笔数不变（真机上验的是「同源重复不产生第二笔」）
- [ ] **导入一份没有交易单号的账单**，其中有两行同商户同时刻同金额：
      应逐组要求确认，**没说「完成」之前不能提交**
- [ ] 疑似重复选「只保留一笔」后提交：账本里只多一笔

## 三、导入：撤回

- [ ] 导入后立刻**撤回**：核对页 / 首页 / 月报的金额同步回落
- [ ] 导入后**先给某笔分好类，再撤回**：那一笔应被保留，弹窗里说明
      「保留 N 笔 —— 你已经给它们分过类」
- [ ] **同一笔消费出现在两份账单里**（例如手工造两份带同样交易单号的文件）：
      撤回其中一份，另一份引用的那笔必须留下
- [ ] 撤回后**再点一次撤回**：应安全返回"没有记录需要移除"，不报错
- [ ] **撤回一份账单，而其中某笔消费已被退款关联**（先导入 → 把某笔标成
      「收到退款」并关联它 → 再撤回）：确认框要说清「N 笔退款会解除关联
      并回到待整理（退款本身不会被删掉）」；撤回后那笔退款仍存在、回到待整理，
      原消费的月报净消费变回去
